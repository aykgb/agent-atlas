# 已打开页面自动更新（前端轮询 + 自动检查按挂钟计时）

来源：2026-09-19 用户反馈「页面没有自动更新数据」。现象：页面头部「更新于」停在打开页面的时刻（16:56），后台自动刷新完成后也不变，必须手动点「刷新数据」。

## 现状

- 前端只在加载时请求一次 `/api/meta`（`metadata()`），没有任何轮询；后台索引更新后，已打开的页面不知道数据已变化。
- `watch_index` 用 `time.sleep(30min)` 计时。macOS 睡眠期间该计时暂停：实测 17:29 启动、期间系统睡眠约 16 分钟，第一次自动检查 18:15 才执行（挂钟 46 分钟）。
- 自动检查只更新本机索引、不自动同步远端，这条不变。

## 方案

前端：页面可见时每 60 秒请求 `/api/meta`，对比数据版本（`updated`、`turns`、`sessions` 拼接）；版本变化则重新 `metadata()` 并重载当前页（`load()`）。从后台切回前台（`visibilitychange`）立即对比一次。请求失败静默，下个周期重试。

后端：`watch_index` 改为挂钟 deadline（`time.time() + interval`），用 `sleep_until(deadline, step=60)` 分片睡眠；系统睡眠唤醒后最多 60 秒内到期补查，正常运行时检查节奏不变。

## 验收

1. 页面打开期间后台完成索引刷新：60 秒内「更新于」自动变化、数据刷新，无需手动点击。
2. 页面从后台切回前台：立即对比一次版本。
3. 系统睡眠跨过检查点时，唤醒后 60 秒内执行自动检查（单测用假时钟模拟睡眠，`sleep_until` 提前到期）。
4. `unittest`、`node --check static/app.js` 通过；CDP 冒烟：触发 `/api/refresh` 后页面自动更新。

## 实测（2026-09-19，本机 macOS）

- `unittest` 29 项全过（含新增 `sleep_until` 分片与唤醒提前到期），`node --check static/app.js` 通过。
- 服务重启后 CDP 打开页面，头部显示「更新于 09/19 18:15」；随后 `curl -X POST /api/refresh`（本机、带 `X-Stats-Request`）触发索引更新（meta 变 18:42），页面在下一个轮询周期内自行变为「更新于 09/19 18:42」，会话数 749→750、轮数 4,117→4,119，无需点击；浏览器控制台无报错。

## 非目标

- 不做 WebSocket / SSE 推送；不自动同步远端（远端新增数据仍需手动同步，本页触发的同步本来就会刷新页面）。
- 不改自动检查的 30 分钟间隔与「只更新本机索引」的边界。
